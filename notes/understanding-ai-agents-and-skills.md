# 如何理解 AI Agent 与 Skill（渐进式暴露）

*学习笔记：梳理对 Agent、LLM、Tool、Skill、API 的关系，并纠正常见误区。*
*对应博文：`_posts/2026-08-01-understanding-ai-agents-and-skills.md`*

## 1. 先从直觉出发

常见的第一版理解大致是：

- Agent 是帮 LLM 做事的工具
- LLM 相当于大脑，给 Agent 发指令
- 流程：人告诉 Agent 目标 → Agent 把想法和 tool 告诉 LLM → LLM 告诉 Agent 怎么做 → Agent 动手 → 再交给 LLM 检查 → 没问题就交回给人
- API 像 LLM 接口的钥匙
- Skill 像 tool 的说明书，说明怎么用、何时用

这幅画面里，**目标闭环**、**API 是通道**、**Skill 是说明书**这几块方向是对的；需要改的是 **Agent 与 LLM 谁在编排谁**。

## 2. 需要倒过来的关系

| 第一版说法 | 更准确的说法 |
|-----------|-------------|
| Agent 是帮 LLM 做事的工具 | **Agent = 会规划、会调用工具、会循环执行的系统**；LLM 是其中的推理引擎 |
| LLM 给 Agent 发指令 | 通常是 **Agent 把上下文发给 LLM，LLM 决定下一步**（调哪个 tool / 写什么 / 是否结束） |
| Agent 把想法和 tool 告诉 LLM | 更像：运行时把 **用户目标 + 可用 tools/skills 说明 + 历史** 一起塞进 prompt |
| 做完再交给 LLM 检查 | 检查不是固定最后一步，而是 **循环里可反复发生**（思考 → 行动 → 观察 → 再思考） |

一句话纠偏：**LLM 不是在给 Agent 打工；LLM 是 Agent 的“大脑”，Agent 才是整套系统。**

## 3. 更完整的一句话模型

```
人（目标）
  → Agent 运行时（编排：记忆、工具、循环、权限）
    → LLM（推理：下一步做什么）
    → Tools / Skills（动手：读文件、搜网页、跑命令……）
    → 观察结果再喂回 LLM
  → 直到达成目标或失败，再交给人
```

真正让系统变成 “Agent” 的，往往是：

**loop（循环）+ state（状态/记忆）+ tools（行动）**

也就是说：不是一次问答，而是多轮「判断 → 行动 → 看结果 → 再判断」，直到停下来。

## 4. 几个概念怎么摆

1. **LLM**：大脑——只会“想”和“说”，本身不能直接改文件、点网页。
2. **Agent**：整个人——大脑 + 手脚 + 工作流程（循环、记忆、约束）。
3. **Tool**：具体能力（搜索、读写、终端、API 调用）。
4. **Skill**：对一组能力/流程的打包说明（何时用、步骤、约定），比单个 tool 的 schema 更偏“工作手册”。
5. **API**：连接通道（调模型、调第三方服务），不是 Agent 本身。

和 Chatbot 的粗分界：Chatbot 主要是单轮/多轮对话；Agent 额外强调 **可行动、可观察、可循环**。

## 5. Skill 为什么说是「渐进式暴露」

Skill 像说明书，但不是一本必须从头读完的书，而是 **有目录、按需展开的手册**。

渐进式暴露（progressive disclosure）的意思是：Skill 的内容 **不是一次性全塞进上下文**，而是分多层、按需加载。

| 层级 | 何时进上下文 | 内容 | 成本 |
|------|-------------|------|------|
| L1 元数据 | 几乎一直在 | `name` + `description` | 每个 skill 大约几十到一百 tokens |
| L2 正文 | 判定「这个任务用得上」之后 | `SKILL.md` 主体（流程、要点） | 几千 tokens 量级 |
| L3 细节 | 正文里点到、且任务真需要时 | `reference.md`、`examples.md`、脚本等 | 不读就 0；脚本甚至只吃输出、不吃源码 |

类比：

- L1 = 图书馆卡片柜（先判断有没有、要不要用）
- L2 = 借出那本手册（核心怎么做）
- L3 = 翻某一附录，或跑某个工具脚本（真需要时再深入）

### 为什么要这样

上下文窗口有限。若把很多 skill 的全部说明都塞进 prompt，会：

- 占满 token
- 用噪声干扰决策
- 让「装很多 skill」变贵

渐进式暴露让你可以装很多 skill：**平时只挂名片，真正相关时再展开说明书，再往下才翻厚附录。**

### 写 Skill 时的实践

1. `description` 写清楚 **做什么 + 何时用**（负责被发现）
2. `SKILL.md` 保持精短（核心流程）
3. 长参考、大例子、脆弱脚本放旁边文件，正文用链接指向它们

一句话：**Skill 是按文件系统分层的知识包；渐进式暴露 = 先发现、再加载、再按需深入。**

## 6. 收束

- Agent 是系统，LLM 是其中的推理引擎，不是反过来。
- Tool 是手脚；Skill 是工作手册；API 是通道。
- Agent 的关键形态是循环：规划 → 行动 → 观察 → 再规划。
- Skill 的关键工程技巧是渐进式暴露：少占上下文，多装能力。
